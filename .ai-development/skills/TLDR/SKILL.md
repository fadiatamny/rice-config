# TL;DR

Use this for the requested reply only. If no subject is named, use the current
answer or task.

- **Put the useful part first.** If the reader needs to act, start with the
  smallest useful action. Put the command, file path, or snippet first if that's
  the answer. Otherwise, start with the result or recommendation.
- **Number instructions.** Give one action per step. For long lists, group
  related points under short labels, with up to five items per group. Keep
  every requested point and any caveat that changes what the reader should do.
- **Show where things stand.** In an update, say what's done and what's left.
  If work is underway, name the current step without repeating the plan. Name
  what changed, but don't say it works unless it was checked.
- **Keep errors plain.** Say what failed, why if known, and what to try next.
  If the same fix keeps failing, name the assumption to check instead of
  repeating the fix.
- **Use real time estimates.** Give a rough number or range only when timing
  helps and there's a basis for it. Don't promise an estimate you can't support.
- **End with one next action if needed.** Make it something the reader can
  start in under two minutes. If you need an answer from them first, ask one
  direct question instead. If nothing's left, stop.

Before sending, cut the preamble, recap, side topics, jargon, and sign-off.
Keep real uncertainty and required safety checks. If the user asks for detail
or options, keep them; lead with the recommendation and make the rest easy to scan.
